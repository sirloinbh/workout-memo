# 로컬 에이전트 요구사항 이슈 작성 예시

아래 코드 블록의 내용을 복사해 GitHub 이슈 본문으로 사용한다. 대괄호로 표시한 항목은 실제 요구사항으로 바꾸고, 완료 기준은 파일·화면·응답처럼 확인 가능한 결과로 작성한다. 예시는 앞으로 요청할 문서 작업이며, 특정 기능의 구현 완료나 발급되지 않은 이슈 번호를 뜻하지 않는다.

````markdown
## 사용자 요구

PC에서 프로젝트를 실행하려는 사용자가 필요한 준비와 실행 순서, 정상 실행 여부를 한 문서에서 확인할 수 있도록 로컬 실행 안내 문서를 작성해 주세요.

## 범위

- [안내 문서 경로]에 한국어 로컬 실행 안내를 작성한다.
- 현재 저장소에서 확인한 준비 조건, 실행 명령, 접속 주소, 종료 방법을 설명한다.
- 기존 README에서 안내 문서로 이동하는 상대 경로 링크를 추가한다.
- 작업은 PC 로컬의 해당 이슈 전용 작업 트리에서 진행한다.

## 완료 기준

- [ ] [안내 문서 경로] 파일이 있고, 준비 조건·실행 순서·정상 실행 확인·종료 방법 제목과 설명이 있다.
- [ ] 명령은 저장소의 현재 설정과 일치하며, 각 명령을 실행할 디렉터리가 표시되어 있다.
- [ ] 정상 실행 확인 항목에는 접속 주소와 사용자가 확인할 화면 또는 응답이 적혀 있다.
- [ ] README의 상대 경로 링크를 따라 안내 문서를 열 수 있다.
- [ ] 실제 변경 내용, 실행한 검증 명령과 결과, 미실행 항목 및 사유가 `docs/changes/<실제 이슈번호>-agent-task.md`에 기록되어 있다.

## 검증 방법

1. 문서의 명령·접속 주소를 현재 설정과 대조하고, 문서 제목과 상대 경로 링크의 대상을 확인한다.
2. 문서 전용 작업이므로 앱 테스트를 추가하거나 기존 테스트를 변경하지 않는다. 호스트에서 기존 `npm run check`로 회귀를 확인하고 실제 결과를 기록한다.
3. 실행 안내를 실제로 따라 확인한 경우 실행 환경과 관찰 결과를 남긴다. 권한·의존성·DB 제한으로 실행하지 못했다면 완료로 기록하지 않고 이유와 남은 검증을 적는다.
4. DB 검증이 필요한 별도 작업에서는 제공된 전용 `TEST_DATABASE_URL`만 사용한다. DB 테스트가 건너뛰어졌다면 성공과 구분한다.

## 제외 범위

- 앱 코드·설정·기존 테스트 변경, 새 도구 도입
- 실제 배포, 별도 저장소 동기화
- 인증 정보, `.env`, 실제 백업, Terraform state의 열람·출력·문서 수록
- 에이전트의 PR 병합·자동 병합·승인

## 요구사항 변경 처리

예: 작업 중 “안내 문서에 오류 해결 항목도 추가해 주세요”라는 요청이 오면, 기존 문서 작성 목표를 유지하면서 추가할 오류 사례와 확인 방법을 정리한다. 이슈의 범위와 완료 기준에 “확인된 오류 사례별 원인·해결 방법을 문서에서 읽을 수 있다”를 반영하고, 변경 사유와 추가 검증 결과를 작업 기록에 남긴다.

앱 설정 변경까지 필요한 요청이라면 현재 제외 범위와 충돌하는 부분을 알리고 범위를 명확히 한 뒤 진행한다. 필요한 답이나 권한이 없으면 차단 사유와 완료한 작업·남은 작업을 구분해 인계한다. 실행하지 않은 검증이나 요청하지 않은 기능을 완료했다고 기록하지 않는다.

## 로컬 작업 및 인계

1. 코디네이터가 실제 GitHub 이슈를 등록하고 그 번호를 포함한 브랜치와 PC 로컬 작업 트리를 준비한다.
2. 테스트 담당이 완료 기준과 기존 검증 방법을 확인하고, 구현 담당이 같은 작업 트리에서 문서와 작업 기록을 작성한다. 구현 담당은 이슈·브랜치를 중복 생성하거나 커밋·푸시·PR 작업을 수행하지 않는다.
3. 구현 후 문서·링크 검사와 호스트 회귀 검사를 수행한다. 리뷰 담당이 요구사항 충족과 변경 범위를 검토하고, 지적 사항을 수정하면 관련 검증을 다시 수행한다. 검증·리뷰 통과 전에는 변경을 커밋하지 않는다.
4. 코디네이터가 검증된 변경을 커밋·푸시하고 PR을 생성하거나 갱신한다. 실행하지 못한 필수 검증이 있으면 그 제한을 명시하고 draft로 인계한다.
5. 사용자가 PR의 변경 내용과 검증 결과를 최종 검토하고 직접 병합한다. 에이전트는 승인이나 자동 병합으로 사용자 검토를 대신하지 않는다.
````

작성 시 프로젝트의 [작업 지침](../AGENTS.md), [구현 절차](../skills/workout-implementation/SKILL.md), [테스트 기준](../skills/workout-testing/SKILL.md)을 확인한다. 현재 실행 방법은 [README](../README.md)를 기준으로 대조한다. 위 역할 구분은 로컬 코디네이터 파이프라인에 인계하는 경우의 예시이며, 실제 작업은 사용자가 지정한 역할과 권한 범위를 따른다.
