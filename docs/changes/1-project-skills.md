- 브랜치: `docs/1-project-skills`
- 목적: 사용자 지정 이슈·브랜치·docs·테스트·PR 절차를 이후 작업에도 적용한다.

## 작업 커밋: docs: 구현 절차와 개발 기반 스킬 추가 (#1)

- `AGENTS.md`에 작업 순서, 계정·원격 저장소, 검사 명령, subtree 동기화 범위를 명시했다.
- `workout-implementation` 스킬에 이슈 재사용, 실제 번호 기반 브랜치, 커밋별 docs 기록, 검증 후 PR, 사용자 전용 병합 절차를 정의했다.
- `workout-foundation` 스킬과 참고 문서에 기존 기술 추천·9개 준비 영역·적용 순서를 정리했다. 추천을 자동 설치 지시와 구분했다.
- README에서 프로젝트 지침과 스킬 원본을 안내했다.
- 저장소 `skills/`를 유지보수 원본으로 삼고 현재 Codex 계정의 `skills/`에는 검증한 사본을 설치한다.
- 검증 결과는 아래에 실행 후 기록한다. 이번 변경은 문서·스킬에 한정되어 앱 빌드·DB·브라우저 테스트를 요구하지 않는다.

## 검증

- skill-creator `quick_validate.py`: 저장소 원본 두 스킬과 Codex 설치본 두 스킬, 총 4회 통과.
- 원본/설치본 `SKILL.md` SHA-256 일치 확인.
- `git diff --check`: 통과. 주요 로컬 문서 링크 대상 존재 확인.
- 검증기에 필요한 PyYAML은 Git에서 제외된 `.local/skill-validator`에만 설치했다. 앱 의존성은 변경하지 않았다.
- 앱 빌드·DB·브라우저 테스트는 실행하지 않았다. 문서·스킬만 변경했고 앱 코드·실행 설정을 변경하지 않았기 때문이다. GitHub CI의 앱 검사는 PR에서 별도로 확인한다.

## 범위와 후속 작업

- 앱 코드·의존성·배포 환경은 변경하지 않는다.
- 새 도구의 설치와 개발 기반 구축은 이후 별도 이슈에서 수행한다.
- PR은 열린 상태로 전달하고 사용자가 직접 병합한다.

## 작업 커밋: docs: 테스트 작성과 커밋·PR 검증 규칙 추가 (#1)

- workout-testing 스킬을 추가하고 구현 절차·개발 기반 스킬과 AGENTS.md에 연결했다.
- 기능 구현·동작 수정은 관련 테스트, 버그 수정은 회귀 테스트를 함께 작성하고 구현·테스트·docs를 같은 커밋에 포함하도록 정했다.
- 커밋 전과 PR 생성·갱신 전 관련 테스트 실행 및 실제 pass/fail/skip·미실행 이유 기록을 요구한다. 코드가 바뀌지 않았고 같은 검증 결과가 유효하면 동일 검사를 불필요하게 반복하지 않는다.
- 테스트 실패를 skip·삭제·assertion 약화로 우회하지 않도록 했다. 필요한 검증을 수행하지 못하면 완료로 보고하지 않고 draft PR로 남긴다.
- 이번 변경은 앱 동작을 바꾸지 않는 스킬·문서 변경이므로 의미 없는 앱 테스트를 추가하지 않았다. 공식 스킬 검증기를 원본 3개와 설치본 3개에 실행해 6회 통과했다.
- 원본·설치본 SHA-256 일치와 git diff --check 통과를 확인했다. PR CI는 새 커밋 기준으로 별도 확인한다.
- 기존 스킬 작업인 열린 이슈 #1·브랜치 docs/1-project-skills·PR #2를 재사용했다. PR #5와 main은 변경하지 않았다.
