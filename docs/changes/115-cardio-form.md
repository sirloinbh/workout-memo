## 변경 — feat: 유산소 기록 부품

- `frontend/src/cardio/format.ts`(새 파일)
  - 종류 이름 9가지(러닝·걷기·실외 사이클·실내 자전거·로잉·계단·일립티컬·수영·기타)와 체감 강도 이름(힘듦·중간·쉬움, #83과 같음).
  - `parseDuration`: 시·분·초 세 칸 → 정수 초. 시는 비워도 됩니다. 칸마다 비었거나 0 이상의 정수여야 하고, 분·초는 0~59입니다("90분"을 1:30:00으로 몰래 바꾸지 않음). 모두 비었거나 합계가 0이면 거부합니다. 24시간 상한은 공유 스키마가 검사합니다.
  - `splitDuration`(수정할 때 세 칸 채우기), `formatDuration`(`1:02:03`, 한 시간 미만은 `32:05`).
  - `formatPace`: 서버가 계산한 초/km → `m:ss/km`. 정수 초로 반올림하며 359.6초는 `5:60`이 아니라 `6:00/km`입니다.
  - `formatSpeed`: km/h, 소수 한 자리. `formatDistance(kind, km)`: km(소수 둘째 자리까지), 수영만 m(`1,500 m`).
  - 거리가 없으면 페이스·속도·거리 함수 모두 `null`이고, 화면은 추정하지 않고 표시하지 않습니다.
- `frontend/src/cardio/api.ts`(새 파일): `lib/api.ts`의 `requestJson` 위의 얇은 함수 `listCardioSessions(from, to)`, `saveCardioSession(body, id?)`(id가 없으면 POST, 있으면 PUT), `deleteCardioSession(id)`. 서버 오류는 `RequestError`의 한국어 메시지로 받습니다.
- `frontend/src/cardio/cardio-form.tsx`(새 파일): 등록·수정 `Modal`
  - 처음에는 종류(선택 상자)·날짜·운동 시간(시·분·초 `NumberInput` 세 칸)·거리 km(`NumberInput`)·체감 강도(`ToggleChips`, 하나 또는 없음)·메모만 보입니다(결정 6).
  - "더 입력하기" 버튼(`aria-expanded`, `aria-controls`)을 누르면 평균·최대 심박, 칼로리, 상승 고도, 케이던스, 시작 시각(`type="time"`, HH:MM), 연결할 근력 일지가 펼쳐집니다. 접어도 입력값은 그대로 저장합니다.
  - 근력 일지 연결: 부모가 넘긴 일지 중 기록 날짜와 같은 날의 것만 고릅니다. 기본값은 "연결 안 함"입니다. 수정하는 기록이 다른 날의 일지에 이미 연결돼 있으면 그 일지도 선택지에 남겨, 날짜를 고쳐도 연결이 말없이 풀리지 않게 했습니다.
  - 저장 전 공유 스키마 `cardioSessionSchemaFor(today).safeParse`로 검사하고, 필드별 메시지를 `FieldError`·`invalidProps`로 입력 아래에 보여 줍니다. 잘못된 값이 있으면 서버로 보내지 않습니다. 오류가 접힌 칸에 있으면 "더 입력하기"를 자동으로 펼칩니다.
  - zod는 필드 오류가 하나라도 있으면 스키마 끝의 교차 검사(오늘 이후 날짜, 최대 ≥ 평균 심박)를 건너뜁니다. 그래서 시간 칸이 잘못돼도 다른 검사가 모두 돌도록 스키마에는 임시로 1초를 넣고 시간 오류는 `parseDuration` 메시지로 따로 붙입니다. 오늘 이후 날짜는 폼에서도 같은 문구로 한 번 더 검사합니다. 날짜 입력에는 `max={today}`도 줍니다.
  - 수정은 전체 교체(PUT)이므로 기록의 `source`·`external_id`를 그대로 다시 보냅니다. 가져온 기록의 중복 판정 키가 남습니다. 새 기록은 `manual`·`null`입니다.
  - 서버 거부(409 중복, 400 등)는 폼 안 저장 버튼 위의 `AlertBanner`로 보여 주고, 폼과 입력값은 그대로 둡니다.
  - 수영을 고르면 "수영 거리도 km로 입력하세요. 1,500 m는 1.5입니다. 목록에는 m로 보여 줍니다." 안내가 나옵니다.
  - 좁은 화면(640px 미만)에서는 시·분·초가 한 줄에 하나씩 쌓입니다. `NumberInput`의 −·+ 버튼(터치 44px 두 개)을 세 칸 나란히 두면 390px에서 입력란이 거의 남지 않기 때문입니다.
- `frontend/src/cardio/cardio-list.tsx`(새 파일): `Card` 안의 `List`. 행마다 날짜·종류, 체감 강도 `Badge`, "시간 · 거리 · 페이스 · 속도", 메모(두 줄까지). 거리가 없으면 "거리 미입력"만 보이고 페이스·속도는 없습니다. 수정·삭제 버튼 이름은 "2026-11-07 러닝 유산소 기록 수정"·"… 삭제"입니다.
- `frontend/src/cardio/cardio-panel.tsx`(새 파일): `from`·`to`·`today`(선택, 기본값 `seoulDate()`)·`workouts`를 받는 독립 패널. 기간의 기록을 불러와 목록과 "유산소 기록 추가" 버튼, 폼을 보여 주고, 저장·삭제 뒤 다시 불러옵니다.
  - 기간이 바뀌면 가장 최근 요청만 목록을 바꿉니다(신체 기록과 같은 방식).
  - 불러오기 실패는 `AlertBanner`와 "다시 연결" 버튼, 빈 기간은 `EmptyState`, 저장·삭제 결과는 `Notice`(`role="status"`)입니다.

  - 새 기록의 날짜는 오늘이 기간 안이면 오늘, 아니면 오늘을 넘지 않는 기간의 마지막 날입니다.

## 결정 3의 수영 거리 표시

결정 3은 "모든 종목을 페이스 분:초/km와 속도 km/h로 똑같이 보여 주고, 수영의 m 표시(#114 결정 A)를 거리 표시에만 남길지는 구현 PR에서 검토"하라는 것이었습니다. 이 PR은 **거리만 m로 남기는 쪽을 권장안으로 구현**했습니다.

- 수영 기록은 수영장 길이(25·50 m)와 바퀴 수로 생각하므로 "1.5 km"보다 "1,500 m"가 바로 읽힙니다.
- 페이스·속도는 다른 종목과 똑같이 `m:ss/km`·`km/h`입니다(예: 1,500 m를 40분 → `26:40/km`, `2.3 km/h`). 종목끼리 비교하는 통계(PR ②)가 단위 하나로 계산됩니다.
- 입력은 다른 종목과 같은 km 칸입니다. 수영을 고르면 m→km 안내를 보여 줍니다. 수영만 m로 입력받을지는 아래 "남은 일"에 적었습니다.

## 한계와 남은 일

- 아직 앱 어디에도 연결하지 않았습니다. 운동 일지의 근력/유산소 탭과 390px e2e·화면 공통 검사(`e2e/ui-*`) 갱신은 PR ③, 통계·대시보드 요약은 PR ②입니다. 연결 전이라 knip이 `CardioPanel`을 쓰지 않는 내보내기로 경고할 수 있습니다(CI에서 경고만).
- 실제 브라우저의 모양(모달 높이, 390px 배치, 날짜·시각 입력의 휴대폰 키패드)은 jsdom으로 확인하지 못했습니다. PR ③의 e2e에서 확인합니다.
- 수영 거리를 m로 입력받을지(지금은 km 칸 + 안내)는 사용자 확인이 필요합니다.
- 유산소 기록에는 낙관적 잠금이 없어(#114), 같은 기록을 두 기기에서 고치면 나중 저장이 이깁니다.
- 기간 밖 날짜로 고쳐 저장하면 기록은 저장되지만 지금 목록에서는 사라집니다(신체 기록과 같음).

- 이 PR은 구현을 하위 에이전트에 맡겼습니다. 주 에이전트가 코드를 읽고 `npm run test -w frontend -- src/cardio`(15 pass), `npm run typecheck -w frontend`, eslint, prettier를 다시 돌려 확인했습니다.
