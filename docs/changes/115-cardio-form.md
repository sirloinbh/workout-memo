## 변경 — feat: 유산소 기록 부품

- `frontend/src/cardio/format.ts`(새 파일)
  - 종류 이름 9가지(러닝·걷기·실외 사이클·실내 자전거·로잉·계단·일립티컬·수영·기타)와 체감 강도 이름(힘듦·중간·쉬움, #83과 같음).
  - `parseDuration`: 시·분·초 세 칸 → 정수 초. 시는 비워도 됩니다. 칸마다 비었거나 0 이상의 정수여야 하고, 분·초는 0~59입니다("90분"을 1:30:00으로 몰래 바꾸지 않음). 모두 비었거나 합계가 0이면 거부합니다. 24시간 상한은 공유 스키마가 검사합니다.
  - `splitDuration`(수정할 때 세 칸 채우기), `formatDuration`(`1:02:03`, 한 시간 미만은 `32:05`).
  - `paceOf`·`speedOf`: 저장된 `duration_sec`·`distance_km`로 초/km와 km/h를 화면에서 계산합니다. 서버가 반올림한 `pace_sec_per_km`·`speed_kmh`를 다시 반올림하지 않으려는 것이며(1차 리뷰), 서버 값은 거리가 없을 때의 대체값으로만 씁니다.
  - `formatPace`: 초/km → `m:ss/km`. 정수 초로 반올림하며 359.6초는 `5:60`이 아니라 `6:00/km`입니다.
  - `formatSpeed`: km/h, 소수 한 자리. `formatDistance(kind, km)`: km(소수 셋째 자리까지, `42.195 km`), 수영만 m(`1,500 m`).
  - `optionalNumber`: 선택 숫자 칸의 글자 → 숫자. 빈 칸은 `null`, 일반 소수(쉼표 소수점 허용)만 숫자로 읽고 나머지는 `NaN`으로 바꿔 스키마가 "숫자로 입력하세요"를 붙이게 합니다.
  - `kmToMetres`·`metresToKm`(부동소수 오차 없이 km↔m), `sessionLabel`(버튼 이름과 삭제 확인 문구).
  - 거리가 없으면 페이스·속도·거리 함수 모두 `null`이고, 화면은 추정하지 않고 표시하지 않습니다.

## 결정 3의 수영 거리 표시

결정 3은 "모든 종목을 페이스 분:초/km와 속도 km/h로 똑같이 보여 주고, 수영의 m 표시(#114 결정 A)를 거리 표시에만 남길지는 구현 PR에서 검토"하라는 것이었습니다. 이 PR은 **거리만 m로 남기는 쪽을 권장안으로 구현**했습니다.

- 수영 기록은 수영장 길이(25·50 m)와 바퀴 수로 생각하므로 "1.5 km"보다 "1,500 m"가 바로 읽힙니다.
- 페이스·속도는 다른 종목과 똑같이 `m:ss/km`·`km/h`입니다(예: 1,500 m를 40분 → `26:40/km`, `2.3 km/h`). 종목끼리 비교하는 통계(PR ②)가 단위 하나로 계산됩니다.
- 입력 단위는 아래 "수영 거리 입력"(2026-11-08 사용자 결정)을 따릅니다.

## 수영 거리 입력 (2026-11-08 사용자 결정)

- 종류가 수영이면 거리 칸은 m입니다(라벨 "거리 m (선택)", 안내 "수영 거리는 m로 입력합니다. 저장할 때 km로 바꿉니다.", −·+ 단위 25 m). 저장할 때 `distance_km = m / 1000`으로 바꿉니다. 스키마의 소수점 셋째 자리(1 m) 규칙에 맞도록 m는 1~1,000,000의 정수만 받고, 아니면 "수영 거리는 1~1,000,000 m의 정수로 입력하세요"를 보여 줍니다.
- 종류를 바꾸면 이미 입력한 값을 같은 거리로 바꿉니다. 러닝 "5"(km) → 수영 "5000"(m), 수영 "1500" → 러닝 "1.5". km 종목끼리 바꿀 때와 읽을 수 없는 글자는 그대로 둡니다.
- 수영 기록을 수정하면 저장된 km를 m로 바꿔 보여 줍니다(1.5 → "1500").
- 예전 안내 "1,500 m는 1.5입니다"는 지웠습니다.

## 1차 리뷰 보완

1. 삭제 실패 표시(필수): 404가 아닌 삭제 실패는 불러오기 실패 배너("다시 연결")가 아니라 삭제 전용 `AlertBanner`로 보여 주고 다시 불러오지 않습니다. 다시 불러와도 지워지지 않으며, 다음 삭제·추가·수정을 시작할 때 지웁니다. 404는 "이미 삭제된 기록입니다"를 알리고 다시 불러옵니다.
2. 불러오는 중 표시: 처음 불러올 때와 `from`·`to`가 바뀔 때만 보입니다. 저장·삭제 뒤 다시 불러올 때는 목록과 포커스 대상이 사라지지 않습니다. 기간이 바뀌거나 불러오기가 실패하면 목록을 비워 이전 기간의 행이 새 기간 아래 남지 않습니다.
3. 버튼 이름: 같은 날 같은 종류의 기록이 둘이어도 겹치지 않게 시작 시각(없으면 운동 시간)을 넣었습니다. 삭제 확인 문구도 같은 이름을 씁니다.
4. 시·분·초 라벨: `.legacy .modal label`(style.css)이 붙이는 아래 여백 17px·세로 배치를 거리 라벨처럼 `mb-0`으로 없애 입력란과 줄을 맞췄습니다.
5. 심박 교차 검사: 최대 ≥ 평균 심박을 오늘 이후 날짜처럼 폼에서 직접 검사해, 다른 칸이 틀려도 함께 보입니다. "다른 검사가 모두 돈다"던 기록 문구를 바로잡았습니다.
6. `optionalNumber`: 일반 소수 패턴(쉼표 소수점 허용)으로 먼저 검사합니다. `0x10`·`1e3`·`Infinity`처럼 `Number()`만 통과하는 글자는 몰래 바꾸지 않고 해당 칸에 "숫자로 입력하세요" 오류를 냅니다.
7. 다른 날 일지 연결: 수정하는 기록이 다른 날짜의 일지에 연결돼 있으면 "다른 날짜(YYYY-MM-DD)의 근력 일지에 연결돼 있습니다." 안내를 보여 줍니다(같은 날 안내 대신). 수정 저장 시 PUT 본문에 그 연결이 남는 것을 테스트로 고정했습니다.
8. 페이스·거리 표시: 페이스·속도는 `duration_sec`·`distance_km`로 화면에서 계산해 한 번만 반올림합니다(서버 값은 대체값). km 거리는 소수 셋째 자리까지(`42.195 km`) 보여 줍니다.
9. 사용자 결정(2026-11-08): 수영 거리는 m로 입력받고 저장할 때 km로 바꿉니다. 종류를 바꾸면 같은 거리를 유지하도록 값을 바꿉니다(위 "수영 거리 입력").
10. 이 기록 문서를 위 내용과 테스트에 맞게 고쳤습니다. 늘어난 테스트: 늦게 온 이전 기간 응답 무시, 삭제 404·500, 다른 날 일지 연결 유지, 수영 m 입력·종류 전환·수정, 버튼 이름 구분, 일반 소수 검사, 한 번만 반올림한 페이스.

  - 검증: 오늘 이후 날짜와 운동 시간 0을 함께 표시(`aria-invalid`, `aria-describedby` 메시지), 심박 20은 접힌 칸을 자동으로 펼치고 범위 메시지, 최대 < 평균 심박 메시지, 거리 "1e3"·칼로리 "0x10"이 "숫자로 입력하세요"로 막히는 동안에도 최대 < 평균 심박 메시지가 함께 보임. 이 동안 POST 없음.
