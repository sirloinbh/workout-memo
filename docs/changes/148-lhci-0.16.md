# #148 개발 도구 @lhci/cli의 npm audit high 취약점 줄이기

- 이슈: [#148](https://github.com/sirloinbh/workout-memo/issues/148)
- 브랜치: `feat/148-lhci-0.16`
- 중앙 기준: [project-standards#416](https://github.com/sirloinbh/project-standards/issues/416)

## 목적

처음 이슈의 zod·body-parser·undici high는 2026-11-08 조사에서 이미 해결돼 있었습니다(앱 zod 4.6.7, body-parser 2.4.0, undici 8.12.3). 루트 `npm audit`에 남은 high 13건은 모두 CI Lighthouse 단계에서만 쓰는 개발 도구 `@lhci/cli` 0.15.1 경로였습니다. 이 도구를 올려 고칠 수 있는 것을 고칩니다.

## 변경 — chore: @lhci/cli 0.16.0

- 루트 `package.json`: `@lhci/cli` 0.15.1 → 0.16.0(2026-11-08 사용자 결정 A).
- 루트 `package-lock.json`: 사용자가 `npm install --ignore-scripts`를 실행해 갱신했습니다. 에이전트의 `npm install`은 프로젝트 hook이 막습니다.
  - 이 설치가 루트의 `tldts-core`도 7.4.18 → 7.4.20으로 올려, `frontend/package-lock.json`이 루트와 달라졌습니다(CI `standards-check` 실패). `node .standards/lockfiles.mjs --write`로 그 한 패키지만 맞췄습니다. `backend` lockfile은 그대로입니다.
  - lighthouse 12.6.1 → 13.6.0(메이저), puppeteer-core 24 → 25.16.0, chromium-bidi 14 → 157.0.8090-0
  - 루트 zod 3.25.76이 없어지고 zod 4.6.7 하나로 합쳐졌습니다(chromium-bidi가 zod ^4.6.5, `eslint-plugin-react-hooks`가 zod 3·4 모두 허용).
  - extract-zip, tmp, uuid, inquirer·external-editor 경로가 사라졌습니다.
- 엔진 요구 node >=22.19.0은 공통 node 24.21.0으로 충족합니다.

## 남긴 것 (사용자 결정 A1)

- high 9건은 모두 basic-ftp 5.3.1([GHSA-c475-qrg2-pj4r](https://github.com/advisories/GHSA-c475-qrg2-pj4r), `Client.list()` 디렉터리 목록 해석의 CPU DoS, 6.2.1에서 수정)입니다.
- 경로: `@lhci/cli` → lighthouse·proxy-agent → pac-proxy-agent → get-uri 6.0.5 → basic-ftp ^5. ftp:// 주소의 PAC 파일을 받을 때만 쓰는 코드라 우리 CI와 운영에서는 실행되지 않습니다.
- get-uri 최신 8.0.1도 basic-ftp ^5.3.1을 요구해 상위 패키지를 올려도 고쳐지지 않습니다. `overrides`로 6.x를 강제하는 방법은 get-uri가 허용하는 범위 밖이라 쓰지 않고, 상위 수정을 기다립니다.
- moderate minimatch(eslint 10·typescript-eslint·eslint-plugin-jsx-a11y-x 경로)는 이슈 범위 밖입니다. audit 기준 고친 버전이 없습니다.

## 테스트

- 앱 코드 변경은 없습니다. PR CI(verify·docker-build·e2e-visual)와 Lighthouse 단계 경고 여부로 확인합니다.
- PC 메모리가 부족해 로컬 전체 `npm run check`는 돌리지 않았습니다.
