# #148 Reduce the npm audit high vulnerabilities of the dev tool @lhci/cli

- Issue: [#148](https://github.com/sirloinbh/workout-memo/issues/148)
- Branch: `feat/148-lhci-0.16`
- Central standard: [project-standards#416](https://github.com/sirloinbh/project-standards/issues/416)

## Purpose

The zod, body-parser, and undici highs of the original issue were already resolved in the investigation of 2026-11-08 (app zod 4.6.7, body-parser 2.4.0, undici 8.12.3). The 13 highs left in the root `npm audit` were all on the path of the dev tool `@lhci/cli` 0.15.1, which is used only in the CI Lighthouse step. I upgrade this tool to fix what can be fixed.

## Change — chore: @lhci/cli 0.16.0

- Root `package.json`: `@lhci/cli` 0.15.1 → 0.16.0 (user decision A of 2026-11-08).
- Root `package-lock.json`: updated by the user running `npm install --ignore-scripts`. The agent's `npm install` is blocked by the project hook.
  - This install also raised `tldts-core` in the root from 7.4.18 to 7.4.20, so `frontend/package-lock.json` differed from the root (CI `standards-check` failed). I aligned only that one package with `node .standards/lockfiles.mjs --write`. The `backend` lockfile is unchanged.
  - lighthouse 12.6.1 → 13.6.0 (major), puppeteer-core 24 → 25.16.0, chromium-bidi 14 → 157.0.8090-0
  - The root zod 3.25.76 is gone and merged into the single zod 4.6.7 (chromium-bidi needs zod ^4.6.5, and `eslint-plugin-react-hooks` allows both zod 3 and 4).
  - extract-zip, the old tmp, yauzl, tar-fs, and `@puppeteer/browsers` 2.x are gone, and uuid went from 8.3.2 to 14.0.3 and inquirer from 6.5.2 to 8.2.7, so the high and low advisories for them disappeared (the old external-editor was replaced by `@inquirer/external-editor`).
  - Following lighthouse 13, `@sentry/node` went from 7 to 11 and `@sentry/bundler-plugins`, `dotenv`, and others were newly added. All of them are on dev dependency paths.
- No production dependency (react, express, pg, vite, and so on) changed version. The zod 4.6.7 of frontend and backend is the same version that just moved to the root.
- The engine requirement node >=22.19.0 is met by the shared node 24.21.0.

## What was left (user decision A1)

- All 9 highs are basic-ftp 5.3.1 ([GHSA-c475-qrg2-pj4r](https://github.com/advisories/GHSA-c475-qrg2-pj4r), a CPU DoS in parsing a directory listing in `Client.list()`, fixed in 6.2.1).
- Path: `@lhci/cli` → lighthouse and proxy-agent → pac-proxy-agent → get-uri 6.0.5 → basic-ftp ^5. It is code used only when a PAC file is fetched from an ftp:// address, so it does not run in our CI or production.
- The latest get-uri 8.0.1 also requires basic-ftp ^5.3.1, so upgrading the parent package does not fix it. Forcing 6.x with `overrides` is outside the range get-uri allows, so I do not use it and wait for an upstream fix.
- The moderate minimatch (path through eslint 10, typescript-eslint, and eslint-plugin-jsx-a11y-x) is outside the scope of the issue. There is no fixed version according to audit.
