# #198 터치 검사를 클릭 후 화면까지 넓히기

- 이슈: [#198](https://github.com/sirloinbh/workout-memo/issues/198)
- 브랜치: `feat/198-touch-after-click`
- 선행: #104(터치 기기의 입력 글자와 누름 영역)

## 목적

터치 기기 검사(`e2e/ui-touch.spec.ts`)는 페이지를 열었을 때 보이는 요소와 모달 3개만 봤습니다. 클릭해야 열리는 신체 기록 폼, 인바디 미리보기, 펼쳐야 보이는 `details` 안의 요소는 글자 16px, 누름 영역 44px, 가로 넘침 없음을 확인하지 않았습니다.

## 변경 — test: 클릭 후 화면을 터치 검사에 추가

- `e2e/ui-touch.spec.ts`
  - 도우미 `openDetails(root)`: 검사 영역 안의 `details`를 모두 펼칩니다. 페이지 검사와 루틴 폼 검사가 검사 전에 부릅니다. 대상은 운동 기록 목록의 "세트 기록 보기", 루틴 목표 카드의 "12주 전체 목표", 종목 분석의 "분석 기준 안내"·"기록 없는 부위", 루틴짜기 12주 미리보기 등입니다.
  - 새 검사 "신체 기록의 기록 폼과 인바디 미리보기가 기준을 지킨다"(터치 360·390·768px):
    - "신체 기록 추가"로 기록 폼을 열고 검사합니다.
    - "인바디 가져오기"를 열고 CSV 파일(단위 테스트와 같은 4행)을 올려 미리보기 표와 행별 `Checkbox`가 나온 뒤 검사합니다.
  - 루틴 폼(휴식 요일 `Checkbox`, 12주 직접 입력)과 종목 분석 부위 지정 칩은 #102에서 이미 넣었습니다.
- 공통 e2e 도우미(`e2e/support/ui-fixtures.ts`)는 바꾸지 않았습니다. 일지 편집(workout-editor) 관련 spec과 시각 기준선은 #105 작업과 겹쳐 건드리지 않았습니다.
- 시각 기준선(`ui-visual`)은 바뀌지 않습니다. `details`를 펼치는 것은 터치 검사 안에서만 합니다.

## 범위 밖

- 인바디 "사진에서 읽은 글자" `details`는 결과지 사진을 브라우저에서 글자 인식한 뒤에만 나옵니다. e2e에서 글자 인식을 돌리지 않아 이 검사에 넣지 않았습니다. 안의 요소는 `pre` 하나라 누름 영역 대상이 없습니다.

## 테스트

- `npm run typecheck`(e2e 포함), eslint·prettier(바꾼 파일): 통과
- e2e는 PC 메모리가 부족해 로컬에서 돌리지 않았고 PR CI `e2e-visual`(ui-touch 포함)로 확인합니다.
