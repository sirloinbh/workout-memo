## Decisions and findings

- The 16px standard on touch screens: the shared `Input` is 14px at 768px and wider, so it failed the `ui-touch` check (#227, #225). It was fixed by adding `md:pointer-coarse:text-base` on the changed screens.
- Even after switching to shared components, element rules inside `.legacy` (the `p` font size, the `button` 44px, and so on) still apply where no class is given. In #225 the description paragraph stayed at 12px, so `text-body-sm` was added.
- #229: the warning text color had about 4:1 contrast in the light theme, so the text stays `text-foreground` and the warning color is used only for the border, line, and background. The possibility that the live region is not read by a screen reader is a design problem of the central `Notice`, so it was left.
- #226: the period row of the exercise analysis was deferred to the #102 scope (replaced in #239). The negative margin of `.field-error` is handled separately.
- #228: the review's "body-part chip width of about 40px" finding was a misdiagnosis (it was already 44px by a legacy rule). It was corrected in the second review record.
- Split-out issues:
  - [project-standards#415](https://github.com/sirloinbh/project-standards/issues/415) The shared `Checkbox` touch tap target is 42px, so make it 44px. It came from the #231 review. Until it is fixed, the app overrides it with `pointer-coarse:after:-inset-[15px]`.
