## Decisions and findings

- Three agents changed the same `style.css` and visual baselines at once, so the merge order overlapped. The merge rule: merge as is only when the head CI (including e2e-visual) passed, the state is CLEAN, and main has not changed `style.css`, `components/**`, `e2e/**`, `package*.json`, or `shared/**` since the branches diverged. Otherwise, merge `origin/main` and run CI again. Right before merging, check separately with `git merge-base --is-ancestor origin/main HEAD`.
- #231: the 44px rule of `.legacy button` enlarged the shared `Checkbox` box, and when the box was restored the `::after` tap target was 42px. It was fixed with `pointer-coarse:min-h-4 pointer-coarse:min-w-4 pointer-coarse:after:-inset-[15px]` (the same for the #233 rest days and the #236 InBody preview). The touch e2e also checks the checkbox box size.
- #232: the review caught overlapping columns on a narrow screen, overlapping in the legacy `.modal label`, and a problem where a non-numeric value could discard the whole draft. The 0.25kg step check of the total weight was split into #234.
- [#234](https://github.com/sirloinbh/workout-memo/issues/234) User decision (closed as not planned): do not enforce the 0.25kg step of the set total weight and do not round automatically. The step buttons move by 5kg, a directly typed value is saved as is, and the DB (`numeric(7,2)`) stores up to two decimal places (100.125 → 100.13).
- #233: fixed the empty cell in the exercise row. The suggested `grid-flow-dense` was not used because it makes the tab order differ from the screen order.
- #125 (#241): only on phones (under 768px) focus and scroll move to the detail, and when the user returns to "운동 목록" (workout list), focus goes back to the chosen exercise button. On wide screens focus stays on the list. With fixed data, the vertical length went from 2,679 to 1,090px at 390px, and from 2,291 to 1,140px at 1280px.
- All visual baselines were updated after directly viewing the CI `visual-baselines` images.
- Production: when #239 was checked, #240 had already merged, so it was not possible to tell whether CSS `BUn0QHaA` was a build of #239 alone. The production CSS just before the #241 merge was `C4wYKDIG`. #231, #235, #232, and #236 have no checks of their own, but they merged before the confirmed builds.
