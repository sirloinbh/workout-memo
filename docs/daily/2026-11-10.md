## 결정과 발견

- [#124](https://github.com/sirloinbh/workout-memo/issues/124) 사용자 결정
  - 입력 UI는 앱 전용 Combobox(WAI-ARIA, 새 패키지 없음, 터치 44px)다. 중앙 공통 Combobox 요청은 [project-standards#437](https://github.com/sirloinbh/project-standards/issues/437)이다.
  - 후보 출처는 새 API다.
  - 비슷한 이름(공백·대소문자만 다름)은 안내만 하고 자동으로 바꾸지 않는다.
  - 종목 분석 부위 지정에는 운동명 입력란이 없어(기록된 운동을 골라 지정) 자동완성 대상이 아니다.
- #258 첫 동기화본은 공통 `Checkbox` 클래스 사이 공백이 빠져 CI가 실패했다. 병합을 보류하고 중앙에 [project-standards#433](https://github.com/sirloinbh/project-standards/issues/433)을 등록했고, 고쳐진 동기화본이 병합됐다.
- Combobox 리뷰에서 잡은 것
  - 목록 이름에 입력란 이름("운동명")이 들어 있으면 Playwright `getByLabel`이 부분 일치로 두 요소를 찾아 e2e가 깨진다. 목록 이름은 "이전에 쓴 이름"이다.
  - `<label>` 안의 후보를 클릭하면 클릭이 입력란으로 넘어가 목록이 다시 열렸다.
  - 편집 창(Radix Dialog)은 Esc를 document 캡처 단계에서 받으므로, 목록이 열렸을 때만 window 캡처에서 먼저 막는다.
- 저장 상태 줄(`role="status"`)을 저장 중에만 다른 감싸개로 옮기면 새로 만들어져 낭독기가 놓칠 수 있다(#270 리뷰). 감싸개를 늘 두고 스피너만 넣고 뺀다.
- 프런트 전체 테스트를 한 번에 돌리면 `routines.test.tsx`의 긴 테스트 1개가 15초 제한에 걸린다. 따로 실행하면 통과한다(#270·#273에서 같은 현상).
- 이 PC 셸의 `TEST_DATABASE_URL`은 다른 프로젝트 DB를 가리킨다. 이 앱의 DB 통합 테스트는 CI에서 확인했다(#273 `verify`).
- #109 PWA를 agent1에 배정했다. `sw.js`·manifest·`offline.html`·`nginx.conf`는 중앙 관리 파일이다. 사용자 결정
  - 새 버전이 넘겨받으면 안내와 [새로고침] 버튼만 보여 주고 자동 새로고침은 하지 않는다.
  - 오프라인은 `offline.html`을 유지하고, 저장 실패 문구를 초안 보존 안내로 바꾼다. 앱 셸 캐시는 #106·#107 뒤로 미룬다.
  - 직접 작성한 `sw.js`를 유지하고 `vite-plugin-pwa`는 쓰지 않는다.
  - localhost 운영 빌드에서 설치 판정·서비스 워커 등록·오프라인 이동을 1회 확인해 기록한다. 실기기·운영 확인은 #106 뒤에 한다.
  - `/api/`는 캐시하지 않는다(#107 401 처리와 겹치지 않게).
