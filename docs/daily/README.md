# Daily work log

Each workday's summary is kept in a `YYYY-MM-DD.md` file. Dates use Asia/Seoul time.

## Writing and retention rules

- The main agent writes or updates the log for a date at the end of the workday, or when the user asks for a wrap-up.
- Extra work on the same day goes into the existing file. The next workday gets a new date file. Days without work get no empty log.
- Briefly record the main work, the real verification results, issues and PRs, and the done, waiting, and blocked states confirmed that day. Do not record work that was not run as done.
- Do not overwrite a past date's state with today's state. When you correct a factual error, leave the reason for the correction.
- When you create a new log, add it to the top of the list below. The latest to-do items are managed in [next-steps](../next-steps/README.md).
- No scheduler generates these at a fixed time. The existing per-issue and per-commit [change records](../changes/) are kept too.
