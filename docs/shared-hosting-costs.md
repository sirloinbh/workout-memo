# 개인용 앱 8개를 위한 공유 호스팅과 월 비용

요금 확인일: **2026-10-15 (Asia/Seoul)**. 서울 리전(`ap-northeast-2`)에서 작은 개인용 서비스 8개를 운영하는 향후 대안을 정리한다. 실제 배포·부하 테스트·계정 청구액 조회는 수행하지 않았다.

## 공유 운영의 전제

앱 8개가 각각 작은 개인용 서비스이고 동시 사용자가 적다면 앱별 서버 대신 서버 한 대와 PostgreSQL 인스턴스 한 대를 공유하는 구성을 초기 대안으로 삼는다. 텍스트·숫자 중심 데이터는 저장량이 작은 편이지만 앱 수만으로 RAM·CPU 요구량을 보장할 수 없다.

공유 DB는 공통 테이블에 모든 앱 데이터를 섞는 의미가 아니다. 한 PostgreSQL 인스턴스에서 앱별 데이터베이스 또는 스키마와 접근 권한을 분리한다.

## 운영 대안

### 1. 저렴한 공유 서버

Linux Lightsail 한 대에 앱 8개와 PostgreSQL을 함께 운영한다. 공인 IPv4와 SSD가 포함된 기본 서버 요금은 다음과 같다. [Lightsail 공식 요금](https://aws.amazon.com/lightsail/pricing/)

| RAM    | 기본 월 요금, 세전 |
| ------ | -----------------: |
| 0.5 GB |                 $5 |
| 1 GB   |                 $7 |
| 2 GB   |                $12 |
| 4 GB   |                $24 |

사용자가 제안한 월 $7~10은 가장 작은 서버 중심의 시작 비용 아이디어이며 백업·이미지 저장 등을 포함한 보장 견적이 아니다. 특히 0.5~1 GB는 앱 8개와 DB를 상시 실행하기에 여유가 매우 적다. 2 GB/$12부터 검토하되 실제 앱의 상주 메모리와 동시 사용량을 측정하고 4 GB 이상으로 올릴 수 있다. 사양별 운영 가능성은 검증하지 않았다.

### 2. 앱 서버와 관리형 DB 분리

앱 서버와 RDS PostgreSQL 등 관리형 DB를 분리하면 자동 백업·유지관리 부담을 줄일 수 있다. 계정·보안·복구 확인 책임은 여전히 운영자에게 있다.

사용자가 제안한 월 **3만~6만원 이상**은 초기 예산 범위이며 확정 RDS 견적이 아니다. 실제 선택 시 서울 리전의 DB 인스턴스 종류, Single-AZ/Multi-AZ, 스토리지, 백업, IPv4, 전송 및 앱 서버 비용을 합산해 다시 계산한다. 이번에는 세부 구성을 확정하지 않았다. [RDS PostgreSQL 공식 요금](https://aws.amazon.com/rds/postgresql/pricing/)

### 3. 정적 프런트엔드 호스팅

정적 프런트엔드는 Amplify 등으로 배포할 수 있다. 운동일지의 Express API와 PostgreSQL까지 정적 호스팅만으로 실행할 수는 없으므로 별도 실행 환경이 필요하다. 빌드·저장·전송 비용, SSR을 사용할 때의 요청·컴퓨팅 비용, 별도 API·DB 비용을 구분해 계산한다. 저트래픽이라도 8개 앱 전체가 무료라고 단정하지 않는다. [Amplify 공식 요금](https://aws.amazon.com/amplify/pricing/)

## 공유 서버의 월 비용 예시

아래는 **서버 한 대 전체 합계이며 앱당 요금이 아니다.** 서울 리전에서 한 달 상시 운영하고 포함 트래픽 이내로 사용하며 프리 티어·가입 크레딧·약정 할인을 적용하지 않는다고 가정한다. ECR 총 과금 저장량은 5 GB-month, Lightsail 총 과금 스냅샷 저장량은 20 GB-month로 가정한다.

| 항목과 계산식                       |  2 GB 서버 |  4 GB 서버 |
| ----------------------------------- | ---------: | ---------: |
| Linux Lightsail, 공인 IPv4·SSD 포함 |     $12.00 |     $24.00 |
| ECR: 5 GB-month × $0.10             |      $0.50 |      $0.50 |
| 스냅샷: 20 GB-month × $0.05         |      $1.00 |      $1.00 |
| 월 합계, 세전                       | **$13.50** | **$25.50** |

합계는 각각 `$12 + $0.50 + $1.00 = $13.50`, `$24 + $0.50 + $1.00 = $25.50`이다. 저장 단가는 [ECR 공식 요금](https://aws.amazon.com/ecr/pricing/)과 [Lightsail 스냅샷 요금](https://aws.amazon.com/lightsail/pricing/)을 기준으로 한다.

8개 앱의 이미지가 합계 5 GB를 넘거나 백업 용량이 늘면 비용도 증가한다. ECR 저장량은 레이어 공유와 실제 보관량에 따라 달라진다. 스냅샷 20 GB-month는 보관된 전체 과금 데이터에 대한 가정이며, 일일 20 GB 백업을 무제한 보관하는 비용이 아니다.

### 설명용 원화 환산

환율을 **$1 = 1,400원**, VAT **10% 적용**으로 가정한다. 세전 원화는 `월 USD × 1,400`, 세후 원화는 `세전 원화 × 1.10`이다.

| 구성         | 월 세전 원화 | 월 세후 원화, VAT 가정 |
| ------------ | -----------: | ---------------------: |
| 2 GB: $13.50 |     18,900원 |               20,790원 |
| 4 GB: $25.50 |     35,700원 |               39,270원 |

실시간 환율이나 계정 실제 청구액이 아니다. 실제 결제 환율·세금·카드 수수료에 따라 달라진다. 따라서 사용자가 제안한 월 **1만5천~3만원**은 저부하·작은 사양의 시작 예산이고, **2만원 안팎**은 2 GB 예시의 조건부 추정이다. 4 GB 또는 별도 관리형 DB를 선택하면 이 범위를 넘을 수 있다.

## 운영 시 확인할 사항

- 공유 서버 장애는 앱 8개 전체에 영향을 준다. 단일 서버 구성으로 고가용성 구성이 아니다.
- 앱별 자원 사용과 DB 연결 수를 관찰한다. 이미지 빌드는 가능한 CI에서 수행해 서버의 메모리 부담을 줄인다.
- DB 논리 백업과 서버 외부 백업 보관·복원 확인을 계획한다. 스냅샷만으로 PostgreSQL의 애플리케이션 일관성 있는 복구가 검증된 것은 아니다.
- 로그인 없는 운동일지는 기존 `localhost:8088` 바인딩을 유지하고 SSH 터널·사설 접속을 초기 가정으로 한다. 추가 유료 VPN은 비용에서 제외한다.

## 제외 비용과 현재 구현 범위

예시에서 도메인 구매, 별도 RDS, 로드밸런서, NAT Gateway, 추가 디스크, 유료 CloudWatch 로그, 유료 지원, 초과 트래픽은 제외했다. 이 항목을 추가하면 재산정한다. 인스턴스를 중지하는 것만으로 모든 고정비가 사라지지는 않는다. 보관한 스냅샷·이미지 등의 과금도 확인해야 한다.

현재 저장소는 8개 앱 전체가 아니라 운동일지 앱의 소스다. Terraform에는 ECR 저장소 2개와 $20 예산의 80% 이메일 알림만 정의되어 있으며, 컴퓨팅·운영 DB·HTTPS·배포 워크플로는 아직 없다. ECR 저장소 2개가 8개 앱 배포를 이미 지원하는 것으로 해석하지 않는다. **$20 예산 알림은 요금제나 지출 차단 기능이 아니다.**

공유 운영 구성은 향후 대안이다. 이번 문서 작업에서 앱 코드·Compose·Terraform을 변경하거나 실제 배포하지 않았다. 저장소 코드만으로 AWS 계정의 실제 리소스나 청구액을 알 수 없다.
